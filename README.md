# Smart Director

Smart Director 是一个面向 Left 4 Dead 2 的 SourceMod 特感导演插件。它接管普通特感的配额、生成队列、目标选择和候选位置搜索，同时保留 Tank、尸潮与游戏难度相关的独立规则。

## 运行流程

一次普通补特由以下阶段组成。

### 1. 状态缓存

事件回调维护玩家在线、队伍、存活、倒地、被控和胆汁状态。位掩码用于快速枚举存活生还者和普通特感。

Flow 缓存只在玩家移动达到阈值后更新；读取失败时保留最近一次有效值，避免临时 Nav 查询失败破坏后续调度。

### 2. 波次与队列

主循环根据以下信息判断是否补充特感：

- 最大特感数量；
- 当前存活数量；
- 已发出但尚未完成的生成请求；
- 待生成队列；
- 当前阵容中控制类和范围类特感比例。

队列元素记录待生成的特感类型，在成功或失败后统一结算在途计数。

### 3. 目标选择

默认优先选择进度较高，并且未倒地、未被控的生还者。若没有满足条件的目标，则回退到任意存活生还者。

### 4. 候选位置搜索

地图 NavArea 按 Flow 百分比分入 101 个桶。搜索从目标附近的进度区域开始，并优先考虑前方区域。

候选位置必须通过硬约束：

- 与目标和其他玩家的距离；
- 生还者可见性；
- Hull 占位与碰撞；
- NavArea 高度与可用性；
- 地图进度范围；
- 同一区域的近期生成间隔。

通过硬约束后，当前规则评分负责选择最终位置。

### 5. 生成与恢复

成功生成后记录时间、幽灵占位和调试信息。若 Nav 候选搜索失败，则回退到游戏引擎提供的随机特感生成位置接口。

无论成功还是失败，在途计数和队列状态都必须被结算，避免导演长期认为仍有生成请求未完成。

## 设计边界

候选位置决策分为两层：

### 硬约束层

保证服务器安全与位置合法性，包括距离、可见性、碰撞、Nav 和地图进度。任何学习模型都不能绕过这一层。

### 排序层

在合法候选之间比较质量。当前实现使用手工规则。

计划中的 NNUE 方向只属于实验设计，目前没有作为稳定功能合入：

- 输入应来自现有状态与候选特征；
- 模型只负责合法候选排序或特感类型评估；
- 默认关闭并支持 shadow 模式；
- 模型不可用时回退到当前规则系统；
- 必须记录规则选择、模型选择和最终结果；
- 必须通过固定地图、固定配置和足够回合数的 A/B 验证。

README 不将尚未实现或尚未验证的 NNUE 方案描述为当前能力。

## 模块结构

| 文件 | 职责 |
|---|---|
| `smart_director.sp` | 依赖声明、插件信息和模块装配 |
| `config.inc` | 常量、ConVar、全局状态和数据结构 |
| `api.inc` | Left4DHooks 与生成接口封装 |
| `nav_cache_build.inc` | NavArea 采样、Flow 分桶和异常 Flow 映射 |
| `nav_cache_io.inc` | Nav 分桶缓存的读取与写入 |
| `nav_helpers.inc` | Flow、安全读取、桶顺序、Trace 和通用 Nav 工具 |
| `lifecycle_setup.inc` | 插件初始化、事件注册和资源准备 |
| `lifecycle_run.inc` | 回合状态、主循环、队列处理和难度规则 |
| `state_spawn.inc` | 玩家状态缓存、特感清理、位置生成和执行生成 |
| `waves_debug.inc` | 波次编排、类型统计和调试命令 |
| `logic_admin.inc` | 管理命令、概率逻辑和特殊规则 |
| `phantom.inc` | 幻听效果 |

## 依赖

- SourceMod 1.12 或兼容版本
- SDKTools
- SDKHooks
- Left4DHooks
- SourceScramble
- `function_data.txt` 中对应的 `CDirector::GetMaxPlayerZombies` MemoryPatch 配置

## 编译

将源码目录放入 SourceMod 的 `addons/sourcemod/scripting/`，并确保所有第三方 include 可用：

```text
spcomp smart_director.sp
```

编译成功后，将生成的插件与所需 gamedata/config 文件部署到测试服务器。

## 部署前检查

至少验证：

- 插件加载时没有缺失 native、gamedata 或 MemoryPatch 错误；
- 回合开始和结束时定时器正确创建和释放；
- Nav 缓存能加载，失效时能安全重建；
- 特感数量不会长期超过 `sd_max_si`；
- 生成失败后在途数量不会残留；
- 生还者不可见性和 Hull 检查没有被绕过；
- 引擎回退路径仍能生成合法特感；
- 地图切换和插件重载后状态能够重新初始化。

## 开发纪律

- `main` 与模块化 Draft 分支的状态必须区分；
- 删除代码前需要确认 SourceMod 回调、命令注册和动态调用入口；
- 不把静态检查当作真实编译或服务器运行验证；
- 学习型排序器不得承担合法性、安全恢复或资源清理；
- 实验配置应放在独立分支或文档中，不在 README 堆叠自动生成的 agent 参数。
